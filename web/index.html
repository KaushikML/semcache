A cache in front of an LLM API. Repeated or reworded questions are answered from the cache in milliseconds; identical questions asked at the same moment share one upstream call.

See it work

Each run uses a fresh conversation, so it starts with an empty cache for its context.

1. Repeat

Ask the same question twice. The first goes to the LLM; the second is answered from the cache.

    2. Reword

    Ask it again in slightly different words. The meaning is compared, not the exact text.

      3. The trap

      Two questions that look alike but need different answers. This is where semantic caching can be wrong, shown openly.

        4. Rush

        Send the same new question 16 times at once. Only one call reaches the LLM: requests that arrive while it runs wait and share its answer (COALESCED); later ones find it cached (HIT). A browser opens at most 6 connections per site, so many land as HITs.
